# Этерна — инструментарий мастера v0.6.1

Обновление PWA v0.6: упрощён выбор типа и автоматизирован выбор языкового профиля. Все данные и ключи хранения сохранены.

## Установка обновления

1. В v0.6 экспортируйте общую базу JSON и сохраните его вне приложения.
2. Распакуйте ZIP. Загрузите все файлы в корень прежнего репозитория GitHub Pages с заменой старых (включая новые location-data.js, location-engine.js, location-ui.js и .nojekyll). Не меняйте адрес сайта.
3. После публикации закройте и откройте PWA с интернетом. Проверьте v0.6.1, три вкладки и наличие прежних NPC.
4. После загрузки новой версии проверьте автономный режим. Не очищайте данные сайта и не удаляйте приложение без резервной копии.

## Локации

Вкладка «Локации» — картотека, а не отдельный случайный генератор. Нажмите «+ Новая локация», выберите тип из выпадающего списка 29 типов либо «Другое» и введите собственный тип (универсальные резервные таблицы). Название и тип обязательны. Выберите культуру для генерации названия; для людей при каждой генерации названия автоматически и равновероятно выбирается чешский, польский либо словенский профиль. Остальные культуры используют свой профиль автоматически. Выбор профиля скрыт; уже сохранённые названия не изменяются. В названии используются 50% смысловых, 30% фонетических и 20% фамильных вариантов из Excel v0.6.1. Составные названия стилизованы, не гарантированно правильны лингвистически. Исходная форма и ассоциации показаны под названием, если известны. При ручной правке названия эти сведения очищаются.

«Заполнить пустые поля» сохраняет введённый текст. «Перегенерировать незакреплённые» требует подтверждения и заменяет только восемь генерируемых полей, кроме закреплённых. У каждого поля есть отдельная кнопка ↻ и фиксация. Фиксация действует в текущем редакторе. Без культуры имя не генерируется, но остальные поля заполняются. Тип влияет на описания; культура влияет только на название. Среда — ручное поле. В 65% случаев явный результат «Нет отдельной проблемы или тайны» сохраняется как заполненное поле.

Родительская локация — строка сортировки (папка); отдельной иерархии, вложенных карточек и городского генератора нет. Внутренняя структура, метки и заметки — свободный текст. Картотека поддерживает поиск, фильтры по папке, типу, культуре и избранному. Сохранение обновляет карточку по ID. Для удаления необходимо сначала отвязать связанных персонажей.

## Связи с NPC

Сохраните локацию, затем выберите существующего NPC в блоке «Связанные NPC» и нажмите «Привязать». Можно открыть карточку NPC или отвязать его. В редакторе NPC также есть выпадающий список «Связанная карточка локации». У NPC одна связанная локация, а у локации может быть много NPC. Прежнее текстовое поле «Локация» не изменяется автоматически. Группировка NPC по связанному месту обновляется при его переименовании. Одинаковые названия не приводят к автоматической привязке. При переносе связи с другой локации требуется подтверждение. Привязка и отвязка сохраняются сразу, независимо от несохранённых правок карточки места.

## Резервные копии

Во вкладке «Локации» используйте «Экспорт общей базы JSON» (NPC и локации с ID и связями). Обратный импорт объединяет записи, не заменяет целиком архив; прежний NPC JSON тоже поддерживается. Совпадения и конфликты ID пропускаются, а недоступные ссылки остаются в данных и показываются в редакторе NPC. Перед записью валидируются оба массива и показывается сводка. При ошибке записи NPC после записи локаций выполняется попытка отката локаций; при ошибке отката приложение сообщает об этом. Общий импорт не является облачной синхронизацией. Ограничения: 20 МБ файла, 20 000 записей на тип. В прежней вкладке NPC экспорт/импорт предназначены только для персонажей; общий файл импортируйте во вкладке «Локации».

Локальное хранение: прежний `eterna-npc-archive-v1` и новый `eterna-locations-v1`. Старые текстовые локации и записи NPC остаются. При повреждении одной картотеки общий импорт/экспорт блокируется; исходные данные можно выгрузить в соответствующем разделе. Не очищайте данные сайта без копии.

## v0.7 — города (ручной редактор)

Обновление: сначала экспортируйте общую базу JSON из v0.6.1, затем замените файлы в прежнем репозитории GitHub Pages **всеми** файлами этого архива, включая `city-store.js`, `city-ui.js`, `world-backup.js` и `sw.js`. Не меняйте адрес приложения: хранилище зависит от origin. Перезапустите PWA после публикации и проверьте четыре раздела. Предыдущие инструкции в README относятся к старым версиям.

- Города: папки по региону, поиск (в том числе по объектам), фильтры культуры и региона, избранное. Единственное обязательное поле города — название. Численность текстовая, чтобы записывать приблизительные значения. Экономика и благосостояние объединены. Нет отдельных полей расового состава, государства, истории, архитектуры и текущей ситуации; при необходимости используйте заметки.
- Три вкладки редактора: «Город», «Районы», «Объекты». Девять фиксированных функциональных зон: верхний город, торговый район, рабочий квартал, нижний город, мемориальная зона, порт, подземелья, укрепления, предместья. Состояния: не описан, присутствует, совмещён, отсутствует. Совмещение описывается вручную. У зоны нет отдельной карточки. Кнопка объектов зоны открывает тот же список с фильтром.
- Объект: тип (42 готовых типа + Другое), название, район (необязательный), описание, отличительная особенность и заметки. Название и тип обязательны. «Сохранить объект» добавляет его в черновик города; **«Сохранить город» записывает все изменения в локальное хранилище**. При уходе из редактора с несохранёнными правками появляется подтверждение. При удалении города удаляются его объекты после подтверждения. Объекты в отсутствующей зоне возможны только после предупреждения; смена статуса зоны не удаляет объекты.
- Случайная генерация городов и объектов, связи городов/объектов с NPC не входят в v0.7. Прежние связи NPC с загородными локациями сохраняются.
- Хранилище `eterna-cities-v1` дополняет прежние ключи. Общий экспорт/импорт в «Городах» и «Локациях» использует один формат `{version, characters, locations, cities}`. Старые файлы NPC и локаций поддерживаются. Импорт объединяет записи по ID; конфликтующий город не перезаписывается и не объединяется по отдельным объектам. Все входные данные проверяются до записи; при сбое записи выполняется попытка отката. Не является облачной синхронизацией.
- Проверка: синтаксис JS, браузерный сценарий создания города, описания зоны, создания произвольного объекта, сохранения, повторного открытия из имитированного localStorage, поиска, редактирования, экспорта, импорта, отклонения невалидной базы, переключения прежних разделов и ширины 390 px. Навигация на localhost блокируется средой; реальный service worker и iPad не проверены.

## v0.7.1 — генерация городов (27.11.2026)

Обновление v0.7. Распакуйте ZIP в корень прежнего репозитория GitHub Pages с заменой файлов. Перед обновлением экспортируйте общую базу JSON. После публикации перезапустите приложение и проверьте номер v0.7.1; если старый кэш остался, откройте страницу в сети и повторно перезапустите. Не очищайте данные сайта без резервной копии.

- В карточке города выберите главенствующую культуру и размер. Старые города сохраняют численность и все прежние данные, размер не угадывается.
- Размеры: малый 1 000–2 999 (шаг 100), средний 3 000–9 999 (500), крупный 10 000–24 999 (1 000), очень крупный 25 000–60 000 (2 500). Численность условна.
- «Заполнить пустые поля» генерирует только незаполненные, незакреплённые характеристики. Кнопки поля заменяют результат по запросу. Закрепление действует до выхода из редактора, не запрещает ручное редактирование. Смена культуры, размера, концепта не заменяет уже заполненные зависимые поля; при необходимости перегенерируйте их сами.
- 466 строк контента из Excel eterna-cities-v0.7.1.xlsx. 66 готовых названий: 18 человеческих, по 6 для остальных культур. Использованные имена исключаются без учёта регистра и ё/е; при исчерпании пула ручной ввод. Полис — вручную. Названия стилизованные, не канонические.
- Экономика: 75% по группе сгенерированного концепта, 25% универсальный пул; прочие тематические поля 65/35; если концепт написан вручную, универсальные варианты. Благосостояние независимо. 65% без отдельной проблемы/тайны.
- Порт: состояние устанавливается вручную. Морские результаты доступны только при состоянии «Присутствует» или «Совмещён». Для портового города установите состояние порта до генерации характеристик. Существующий текст не меняется при изменении порта.
- Районы генерируются только отдельно. Первичный бросок зависит от размера. При заданном состоянии генерация меняет лишь описание. Если в зоне уже есть объекты и состояние не задано, первичная генерация выбирает присутствие. Совмещение с явно отсутствующей зоной исключается. Для замены существующего описания запрашивается подтверждение. Никакие объекты не создаются и не перемещаются автоматически.
- Общий JSON включает size и concept_id. Ключи локального хранения прежние. При ручном изменении концепта ID сбрасывается. Генерация объектов и привязка NPC к городам/объектам отложены.
- Проверки: 14 400 полных генераций, 122 400 генераций районов, исчерпание пула имён, миграция, размер/порт, сохранение и общий экспорт/импорт; Chromium с встроенными исходниками и имитацией localStorage, ширина 390 px. Реальные HTTPS, service worker и iPad не проверены.
